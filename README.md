# 百积木桌面微信连接器

这是百积木本地应用，保留应用身份、查询接口以及 `messageReceived`、`contactsChanged` 事件。连接器在本机查询独立微信采集器，把已记录的增量转交 Bridge Agent。微信数据权限、数据库访问和密钥管理都由独立采集器负责。

## 连接

1. 启动 `wechat-desktop-collector`，查看它显示的本机 HTTP 地址和一次性配对码。
2. 在百积木启动本地微信应用，打开状态页，填写地址和配对码，点击「连接」。
3. 查看采集器状态和两路事件的投递状态。采集器使用同一状态目录和端口重启后，连接器沿用现有授权。

管理操作 `pairCollector` 接收 `address` 和 `code`。地址仅支持同机 loopback HTTP；配对后，连接器在自身私有数据目录保存本机地址和访问凭证。

## 查询和投递

百积木继续使用清单声明的会话、账号、联系人、历史、搜索和媒体查询。采集器停机或尚未准备好时，查询返回 `SOURCE_NOT_READY`。

消息和联系人分别拉取。Bridge Agent 返回对应应用和事件 ID 的 `queued` 回执后，连接器确认采集器的待发事件。收到匹配的 `no_subscribers` 时，消息结束投递并确认出队，联系人增量保留并等待订阅。新增订阅需要查询以往消息时可以调用历史查询接口。失败、超时或回执不匹配时用原事件 ID 重试。关闭百积木时采集器可以继续运行。

## 从原采集模式升级

在切换前先停掉原方式的采集进程。用独立应用的迁移参数导入原消息游标和联系人同步状态，再在百积木配对。这样可以接续增量与联系人序号。数据源凭证由用户在独立应用侧按其操作说明配置。

## 开发与发布

运行 `python3 -m pytest -q` 和 `node --test tests/*.test.mjs`。发布仍由已登记的 `wechat-bridge-collector-release` Jenkins 任务验证并构建本应用的源码制品，再以同一应用身份登记。独立采集器有单独的源码和发布生命周期。
