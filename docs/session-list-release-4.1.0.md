# 4.1.0 会话列表与版本例外

## 用户明确授权

2026-10-06，当前用户要求彻底删除会话历史可读性预检及前端禁用逻辑，随后指定发布 4.1.0。
已说明删除公开返回字段 `historyAvailable` 属于不兼容变更，与通常采用 MAJOR 的严格 SemVer 规则冲突；
用户明确答复“本次允许”，批准本次从已发布 4.0.0 到 4.1.0 的版本规则例外。
本例外仅适用于这次准确版本与字段删除，不构成未来版本、依赖或其他兼容变更的授权。

## 行为与消费者影响

`getRecentSessions` 只读取会话摘要与名称，不再为判断历史可读性遍历消息分库，也不返回 `historyAvailable`。
嵌入界面允许打开所有会话，点击后调用原有历史查询；无本地历史记录时显示空状态。
Python、保留的 Rust 实现、界面判断、样式和打包检查同步删除旧逻辑，不提供常量字段或兼容分支。
调用方必须停止依赖该字段。现有母婴运营台源码未使用该字段；其他调用方应按此契约核对。

## 升级与恢复

不改变组件依赖，不修改消息和联系人事件契约，不重置已有采集游标。
本机诊断版本为 3.1.8；升级跨越 4.0.0 时仍须遵守 `contact-sync.md` 的联系人事件消费者前置条件。
发布完成和设备安装验证分别记录；不得把未完成的设备验收或市场独立审核描述为成功。
恢复使用已发布的不可变版本及其适用数据契约，不覆盖旧版本、标签或应用状态。

回归测试要求会话列表在消息数据库不可用时仍返回普通与系统聚合会话摘要，且不访问消息分库。
运行完整 Python、Node 与 Rust 测试，以及清单、版本一致性、语法、归档和发布回读检查。
